The Problem
Why Traditional Recruitment Is Broken
Five interconnected failures that compound into bad hires, wasted budgets, and eroded institutional trust.

Examination Fraud

Candidates use external resources, collaboration, or screen-sharing during online exams with no meaningful supervision in place.

Inflated scores, underqualified hires

Credential Dishonesty

Fabricated degrees, inflated job titles, and falsified certificates are submitted with no verification mechanism.

Unqualified candidates pass screening

Result Tampering

Digital records stored only in SQL databases can be silently modified by insiders — no audit trail exists to detect manipulation.

Recruitment decisions are not trustworthy

Behavioral Blindness

Conventional systems capture only final answers — no insight into reasoning process, hesitation patterns, or real-time behavior.

Character and integrity go unmeasured

Operational Inefficiency

Manual CV reviews, email-based scheduling, and spreadsheet tracking consume weeks of HR time per vacancy.

Slow time-to-hire, poor candidate experience
These five problems compound: a cheated exam + falsified credentials + tampered results = a hired candidate who should never have made it past screening.

Identity Assurance
Biometric Face Verification at Exam Entry
Prevents identity fraud — only the registered candidate can take the exam. Processing runs entirely in the browser; no raw images are transmitted.

Enrollment Phase (Profile Setup)

1
Camera activated — candidate shows face to 5 different angles
2
face-api.js SsdMobilenetv1 detects face and computes 128-dimensional descriptor vector for each frame
3
5 descriptors averaged → stored in database as reference embedding

Verification Phase (Exam Entry)

1
Live webcam frame captured → 128-dim descriptor computed
2
Euclidean distance computed between live descriptor and stored reference
3
Distance < 0.45 threshold → MATCH (exam proceeds). Distance ≥ 0.45 → REJECTED
Test Results
Same person (5 frames) Distance: 0.12–0.39 MATCH ✓
Different person Distance: 0.51–0.93 REJECTED ✓
Test set size 10 individuals × 5 frames 0 false accepts
Processing time 265ms avg · 440ms max In-browser ✓
128-Dim Embedding Space
Each dot = one face descriptor
Privacy by Design: Raw camera frames are never sent to the server. Only the numeric descriptor array is stored. No biometric images are retained after enrollment.

Why Internet Computer Protocol?

No gas fees — unlike Ethereum where each write costs unpredictable ETH gas, ICP canisters run on cycles with stable, predictable costs
Canister model — smart contracts (canisters) serve HTTP requests directly. The ICP gateway Node.js app calls canister methods via the @dfinity/agent SDK
Deterministic execution — the same inputs always produce the same state. No miner ordering games.
320ms write avg — fully asynchronous. Blockchain writes never block the user flow.

Security Design
Defense in Depth — Seven Security Layers
Security is not a single control — it is a layered strategy where each layer assumes the previous one may fail.

AES-256-CBC Exam Encryption

Exam questions are stored as ciphertext in the database. The EXAM_AES_KEY never enters the DB — without it, questions are unreadable. IV is generated fresh per exam.

SHA-256 Document Hashing

CVs, exam anti-cheat logs, and interview transcripts are hashed before being sent to the blockchain. Hash mismatch = proof of data modification.

PDO Parameterized Queries

All database interactions use prepared statements via PHP PDO. User input is never interpolated into SQL strings — SQL injection is structurally impossible.

HTTPOnly Session Cookies

Session tokens set with HttpOnly and SameSite flags. JavaScript cannot access the cookie. XSS attacks cannot steal session tokens.

Account Lockout

After 5 failed login attempts, the account is locked for 15 minutes (login_attempts + locked_until columns). Brute-force attacks are rate-limited at the DB level.

CSRF Protection

All state-changing POST endpoints validate a session-bound CSRF token. Requests from forged origins are rejected before any processing occurs.

Anti-Cheat Outcome Hidden

Candidates never see their integrity outcome (CLEAN/FLAGGED). The cheat_score and violations are accessible only to the hiring company via the admin dashboard.

Blockchain Immutability — The Final Integrity Layer

Even if a database admin modifies a record, the SHA-256 hash stored in the ICP canister will no longer match. The discrepancy is independently verifiable by any party — no trust in a central authority required.
